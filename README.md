# WebRTC Session Manager

Высокопроизводительный микросервис для регистрации и хранения пользовательских WebRTC-сессий.

Проект показывает, как построить небольшой production-oriented backend на **Go**, подключить **PostgreSQL**, упаковать приложение в контейнер и развернуть его в **Kubernetes / MicroK8s** с внешним доступом через **MetalLB**.

Главная ценность проекта — не только готовый сервис, а **практический пример связки Backend + Database + Container + Kubernetes**, который можно использовать как основу для собственных сервисов.

## Что вы получите, изучая проект

Проект поможет на практике разобраться, как:

* создавать HTTP API на Go с использованием `fasthttp`;
* разделять HTTP-обработчики, бизнес-логику и работу с данными;
* сохранять состояние пользовательских сессий в PostgreSQL;
* автоматически инициализировать структуру базы данных;
* собирать Go-приложение в компактный контейнерный образ;
* запускать приложение без Docker daemon с помощью Podman;
* разворачивать backend и PostgreSQL в Kubernetes;
* использовать `ConfigMap` и `Secret` для конфигурации;
* предоставлять Kubernetes-сервису внешний IP через MetalLB;
* работать с локальным кластером MicroK8s;
* проверять работу API и данные непосредственно внутри Kubernetes.

Таким образом, репозиторий можно использовать как **учебный стенд, стартовый шаблон или основу для собственного микросервиса**.

## Архитектура

Проект состоит из нескольких основных компонентов.

### Go Backend

HTTP-сервис отвечает за работу с пользовательскими сессиями.

Для обработки HTTP-запросов используется `fasthttp`, ориентированный на высокую производительность и небольшие накладные расходы.

Бизнес-логика выделена в отдельный слой:

```text
HTTP Handler
     ↓
Service
     ↓
Repository / Database
```

Такое разделение упрощает дальнейшее расширение приложения и тестирование отдельных компонентов.

### PostgreSQL

PostgreSQL используется для постоянного хранения информации о сессиях.

При запуске базы данных SQL-скрипты автоматически создают необходимую структуру.

Это позволяет развернуть проект без ручной подготовки базы данных.

### Kubernetes / MicroK8s

Приложение и PostgreSQL запускаются внутри Kubernetes.

Kubernetes отвечает за:

* запуск контейнеров;
* управление Pod;
* декларативную конфигурацию;
* сетевое взаимодействие;
* хранение конфигурации;
* подключение приложения к базе данных.

### MetalLB

MetalLB используется для предоставления Kubernetes-сервису внешнего IP-адреса в локальной сети.

Это особенно полезно при работе с локальным Kubernetes-кластером, где нет облачного LoadBalancer.

### Podman

Для сборки контейнерного образа используется Podman.

Это позволяет работать с контейнерами без необходимости запускать Docker daemon.

## API

Для регистрации сессии используется HTTP-запрос:

```bash
curl -v -X POST http://10.64.140.43 \
  -d "id=102" \
  -d "user=ivan"
```

IP-адрес в примере зависит от конфигурации Kubernetes и MetalLB.

После обработки запроса данные сессии сохраняются в PostgreSQL.

## Проверка данных

Получить содержимое таблицы `sessions` можно непосредственно из Pod PostgreSQL:

```bash
sudo microk8s kubectl exec -it \
  -n go-webrtc \
  deployment/postgres \
  -- psql \
  -U go_user \
  -d my_app_db \
  -c "SELECT * FROM sessions;"
```

Такой подход позволяет быстро проверить весь путь данных:

```text
HTTP request
     ↓
Go API
     ↓
Business logic
     ↓
PostgreSQL
     ↓
sessions table
```

## Технологии

* **Go** — backend;
* **fasthttp** — HTTP-сервер;
* **PostgreSQL 13** — хранение данных;
* **Kubernetes** — оркестрация;
* **MicroK8s** — локальный Kubernetes-кластер;
* **MetalLB** — внешний IP для сервиса;
* **Podman** — контейнеризация;
* **containerd** — запуск контейнеров в Kubernetes;
* **Protocol Buffers** — описание API.

## Что можно развивать дальше

Проект можно расширить в полноценный сервис управления WebRTC-сессиями:

* реализовать завершение сессии;
* добавить TTL и автоматическое удаление устаревших сессий;

* добавить метрики Prometheus;

* добавить авторизацию;
* покрыть бизнес-логику тестами;
* добавить CI/CD;
* масштабировать backend через несколько Kubernetes Pod.

## Итог

**WebRTC Session Manager** — это компактный практический пример того, как построить backend-сервис на Go и довести его до запуска в Kubernetes.

Репозиторий полезен тем, что объединяет несколько задач в одном проекте: **HTTP API → бизнес-логика → PostgreSQL → контейнер → Kubernetes → внешний доступ**.

Его можно использовать как учебный пример, основу для собственного микросервиса или лабораторный стенд для изучения Go, контейнеризации и Kubernetes.
